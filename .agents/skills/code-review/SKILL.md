# 代码审查

1. 确认用户要求审查的文件、模块或修改范围；范围不明确时先查看项目结构和相关文件。
2. 阅读实际实现及关键调用方，以代码证据判断问题，不根据文件名猜测行为。
3. 需要检查清单时，使用 `read_skill_resource` 读取 `references/checklist.md`。
4. 优先找会改变行为的问题：错误状态、边界条件、资源清理、数据一致性和权限绕过。
5. 需要运行验证时使用现有 `execute_command`，遵守工作区、PLAN 和审批规则；没有执行就明确标记未验证。
6. 输出问题时说明文件位置、具体触发条件、影响和修复方向，按严重程度排序。
7. 没有发现问题时说明审查范围和剩余风险，不为凑数量编造缺陷。除非用户要求修复，否则先报告发现。

不自动提交、推送或修改权限。引用项目约定时按需阅读 AGENTS.md 和相关设计文件。
