# 排查测试失败

1. 获取实际报错、失败测试名称及项目构建方式；缺少日志时先检查项目配置。
2. 阅读失败测试、被测代码和必要调用方，区分代码缺陷、环境问题与测试假设错误。
3. 在权限允许时运行范围最小且能复现的测试命令。单个静态文件没有测试工程时，不随意尝试 Maven、Node 或 Python。
4. 根据失败证据做必要修改，不通过删除断言或跳过测试掩盖问题。
5. 重新运行相关测试；修改影响公共组件时补充适当回归。
6. 需要排查思路时，读取 `references/troubleshooting.md`。
7. 报告根因、修改内容、实际验证结果及尚未完成部分。

PLAN 模式只探索并提出方案；文件修改和命令执行继续服从审批。未收到用户要求时不提交或推送 Git。
